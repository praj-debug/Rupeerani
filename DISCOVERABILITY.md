# Discoverability checklist

This document tracks practical steps to make RupeeRani, StockRani and the founder easier to find through GitHub, search engines, professional networks and relevant communities.

## GitHub essentials

- [x] Lead with a plain-language description of the project.
- [x] Link major project areas from the root README.
- [x] Link the founder's public profiles.
- [ ] Set a concise repository description in GitHub repository settings.
- [ ] Add relevant repository topics: `rupeerani`, `stockrani`, `financial-literacy`, `personal-finance`, `fintech`, `india`, `financial-education` (only where accurate).
- [ ] Add a profile README to the `praj-debug` user account using a public repository named `praj-debug`.
- [ ] Pin the RupeeRani repository on the founder's GitHub profile.
- [ ] Keep dated, evidence-based updates in the progress log.
- [ ] Add clear screenshots and a live demo only when a working product exists.

## Website and search

- [ ] Publish a public website or GitHub Pages landing page with dedicated About, Founder, StockRani, Resources and Collaborate sections.
- [ ] Give each page a unique, descriptive title and clear heading.
- [ ] Link official brand profiles consistently and use the same brand description across channels.
- [ ] Add a sitemap and verify it through Google Search Console once a website/domain is available.
- [ ] Check that pages are public, crawlable, mobile-friendly and do not rely on text embedded only in images.
- [ ] Add meaningful alternative text to informative images and captions/transcripts for video content.
- [ ] Link content to useful tools/resources rather than using generic “link in bio” language everywhere.

## Distribution

- [ ] Include the repository or relevant public page in LinkedIn and creator profiles.
- [ ] Share genuinely useful resources in appropriate communities while following their self-promotion rules.
- [ ] Reach out individually to colleges, educators, financial-literacy initiatives, relevant fintech teams and podcast hosts with a specific collaboration proposal.
- [ ] Use one tracked campaign link per channel or partner when measuring traffic.
- [ ] Reuse the strongest questions from comments and workshops to improve future resources.

## Track outcomes monthly

Record the time period and source for each metric.

| Metric | Where to check | Why it matters |
|---|---|---|
| Repository views and unique visitors | GitHub Insights | Measures GitHub discovery |
| Website clicks and search impressions | Web analytics and Search Console, when configured | Measures external discoverability |
| Tool starts/completions | Product analytics, with privacy-conscious instrumentation | Measures usefulness |
| Partnership enquiries and replies | Outreach log | Measures partnership interest |
| Returning visitors and resource downloads | Website analytics, if implemented | Measures ongoing value |

## Guardrails

- Do not invent followers, traffic, revenue, partners, testimonials, awards or audience demographics.
- Do not keyword-stuff pages or add unrelated GitHub topics.
- Do not collect financial or personal data for analytics unless genuinely necessary and properly safeguarded.
- Distinguish planned products from live products.

## Suggested first milestone

Complete the GitHub metadata, founder profile, collaboration brief and one genuinely useful public resource. Then measure whether people actually find and use it before expanding the scope.
