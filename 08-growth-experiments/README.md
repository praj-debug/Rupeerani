# Growth Experiments

Treat growth as a learning system. Every experiment should have a specific question, measurable outcome and a way to interpret an inconclusive result.

## Experiment process

1. Describe the problem with evidence.
2. State a falsifiable hypothesis.
3. Choose one main variable to test where practical.
4. Define the primary metric and guardrails in advance.
5. Record baseline, dates, audience, platform and limitations.
6. Run the test long enough to be meaningful for the channel and sample size.
7. Record outcome honestly, including null or negative results.
8. Decide whether to adopt, iterate, stop or gather more evidence.

## Example question backlog

These are suggestions, not experiments already run.

- Does a question-led title improve qualified viewing compared with a broad topic title?
- Do captions or on-screen definitions improve comprehension for technical terms?
- Does a recurring content format produce more returning viewers than unrelated topics?
- Which call to action generates useful questions rather than empty engagement?
- Do source notes and clear caveats improve audience trust or save/share behaviour?

## Reporting rule

Never fabricate a baseline, sample size, result or causal conclusion. Distinguish correlation from causation and describe uncertainty when samples are small.
